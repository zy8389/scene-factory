# 网页中的 Franka 仿真验收与回放

网页的“运行机器人任务”区域提供已验证的 Franka 抓杯与放杯流程。每个初始布局
分别执行两项任务，先运行真实 PhysX 稳定性检查，再执行机器人动作。该区域采用
固定的厨房场景和采样分布；上方自然语言生成的其他场景继续使用原有预览和导出流程。

## 启动

在已有网页服务的启动命令中配置 Isaac Python 和官方本地资产入口：

```powershell
scene-factory-web --output <ASCII_WEB_DIRECTORY> --runtime-output <ASCII_RUNTIME_DIRECTORY> --isaac-python <ISAAC_PYTHON> --asset-root <OFFICIAL_LOCAL_ASSETS>
```

Windows 下，运行目录、Isaac Python 和资产入口使用纯 ASCII 路径；必要时使用
已有环境的目录 Junction。资产根目录应包含
`Isaac/Robots/FrankaRobotics/FrankaPanda/franka.usd`。这些配置由本机服务启动参数
管理，网页只选择控制方案和布局数量。

未配置 Isaac 环境时，场景生成、历史结果查看和已记录轨迹回放仍然可用；
开始新仿真按钮会显示环境未就绪的原因。

## 从一个布局开始

1. 打开本机网页，滚动到“运行机器人任务，查看真实结果”。
2. 选择优化控制方案或原始控制方案，布局数先设为 1；对应抓杯与放杯两个任务。
3. 点击“开始仿真验收”。网页立即显示排队状态，后台逐项执行。
4. 在进度和逐项结果中分别查看物理检查、任务结果和证据校验状态。
5. 完成后选择一条有完整记录的任务，播放、暂停、拖动时间轴或调整回放速度。

单个服务只有一个运行队列，任务按顺序使用 Isaac worker。关闭浏览器不终止
后台运行，刷新页面可继续查看进度。服务重启时，中断的任务会保留为中断状态，
不会自动重写证据或重新执行；再次测试会建立新的任务目录。运行队列尚未结束时，
网页不会再开启另一个 Isaac 场景预览。

## 查看已有验收批次

把此前 `dataset run-isaac` 的输出目录作为只读历史接入：

```powershell
scene-factory-web --output <ASCII_WEB_DIRECTORY> --runtime-history <EXISTING_RUNTIME_BATCH>
```

`--runtime-history` 可重复传入，同时查看成功批次和失败基线。服务会重新校验
原始批次证据，历史目录及其清单、质量、日志和轨迹保持原样。没有通过校验的批次
会显示校验错误，不能作为已验证成功结果或进入回放。

## 结果与回放的含义

“运行完成”表示批次完成记录和校验；其中仍然可以有失败任务。
物理通过、任务成功、任务失败、未验证和证据完整分别展示。完整记录的失败轨迹
也可以回放，用于观察失败阶段和夹持接触的变化。

回放逐帧使用记录中的物体位置、末端与双指位置、关节数值和接触证据。
它是状态轨迹的三维显示，当前不包含录制视频或完整机器人连杆模型。
没有记录的物体旋转保持初始布局朝向，页面会显示这一限制。回放入口会核对
文件哈希及轨迹证据，拒绝缺失或被修改的记录。

当前只开放这一 Franka/YCB 杯子任务切片。其他物体、任意自然语言任务和其他
机器人需要分别扩展控制器、任务判据和真实验收；当前成功率不能自动推广到它们。

底层运行门槛与离线校验见[真实运行工作流](RUNTIME_DATA_WORKFLOW.md)。
